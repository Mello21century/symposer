Documentation

symposer is a drop-in front end for Composer. Use it wherever you'd type composer, and packages are stored once and linked into each project.

Install

You need PHP 7.2.5 or newer. You don't need Composer: on first run symposer downloads its own pinned composer.phar and checks it against a sha256 checksum.

macOS and Linux

This picks the right binary for your OS and CPU:

$ curl -fsSL -o symposer "https://github.com/Mello21century/symposer/releases/latest/download/symposer-$(uname -s | tr A-Z a-z)-$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')"
$ chmod +x symposer && sudo mv symposer /usr/local/bin/

Windows (PowerShell)

Installs to your user folder and adds it to your user PATH. No admin rights needed. Open a new terminal afterwards.

> $dir = "$env:LOCALAPPDATA\symposer"; New-Item -ItemType Directory -Force $dir | Out-Null
> Invoke-WebRequest https://github.com/Mello21century/symposer/releases/latest/download/symposer-windows-amd64.exe -OutFile "$dir\symposer.exe"
> [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$dir", "User")

With Go 1.23+

$ go install github.com/Mello21century/symposer@latest

The binary lands in $(go env GOPATH)/bin. Make sure that folder is on your PATH.

Check it works

$ symposer store status   # version, store location, package count
$ symposer --version      # Composer and PHP versions in use

Commands

Every Composer command works. symposer passes the arguments straight through.

$ symposer install
$ symposer update
$ symposer require monolog/monolog
$ symposer remove --dev phpunit/phpunit

The only command of its own is store:

symposer store status
Prints the symposer and Composer versions, the store path, how many packages and versions it holds, and its size.
symposer store path
Prints the store path, handy in scripts.
symposer store prune
Deletes store versions that no project uses anymore. Add --dry-run to list them without deleting.

After each run symposer prints a summary:

symposer: 112 package(s) linked from store, 3 newly stored

Choosing the PHP version

symposer is a native binary, so php74 symposer install won't work. Set SYMPOSER_PHP to a command on your PATH or a full path instead. Composer then runs on that PHP, so dependency resolution and platform checks match it.

# default PHP is 8.3, this project needs 7.4
$ SYMPOSER_PHP=php7.4 symposer install          # Debian/Ubuntu (ondrej PPA)
$ SYMPOSER_PHP=php74 symposer install           # Laravel Herd
$ SYMPOSER_PHP=/opt/homebrew/opt/php@7.4/bin/php symposer install

To keep it for a whole shell session, or as a shortcut:

$ export SYMPOSER_PHP=php81
$ alias symposer81='SYMPOSER_PHP=php81 symposer'   # in ~/.zshrc or ~/.bashrc

On Windows:

> $env:SYMPOSER_PHP = "C:\php74\php.exe"; symposer install     # PowerShell
> set SYMPOSER_PHP=C:\php74\php.exe && symposer install        # cmd

Projects on different PHP versions share one store safely. Every entry is keyed by exact version and commit, so each project links to what its own lock file asks for.

How it works

symposer is one Go binary with a small PHP shim embedded in it. When you run a command, it starts the pinned Composer through that shim. The shim wraps Composer's archive downloaders (zip, tar, gzip, xz, rar, phar, file) and changes nothing else.

  • Store hit: vendor/acme/pkg becomes a link to ~/.symposer/store/acme/pkg/<version>-<ref>/. That's a symlink on macOS and Linux, and a junction on Windows, which needs no admin rights or developer mode.
  • Store miss: Composer downloads the package as usual, with your auth, cache and mirrors. It's extracted into a temporary folder, moved into the store in one atomic rename, made read-only, then linked.
  • Packages with bin scripts get a real folder of hardlinks instead. Tools like Pest locate vendor/autoload.php through __DIR__, and PHP resolves __DIR__ through symlinks.

Composer handles everything else exactly as it would without symposer: resolution, composer.lock, private repositories, plugins and their events, installer-paths, scripts, installed.php and vendor/bin.

The Composer version is pinned (currently 2.11.2) because the shim depends on Composer internals. Each symposer release is tested against the version it ships with.

Opting packages out

A shared store means a package that writes into its own folder would change it for every project. Store files are read-only, so that fails with a clear error instead. Install such a package as a normal copy:

{
  "extra": {
    "symposer": { "exclude": ["vendor/package"] }
  }
}

Packages patched by cweagans/composer-patches are excluded automatically. symposer reads extra.patches, extra.patches-file and patches.json.

Composer's own variables, such as COMPOSER_AUTH, COMPOSER_MEMORY_LIMIT and COMPOSER_NO_INTERACTION, work as usual.

The store

Everything lives in ~/.symposer:

~/.symposer/
  composer-2.11.2.phar      # pinned Composer, downloaded once
  runtime/shim-*.php        # the embedded shim
  projects/*.json           # which store versions each project uses
  store/<vendor>/<name>/<version>-<ref>/

Updating a package links the new version and leaves the old one in the store, so other projects still on it keep working. Removing a package only removes the link. See Cleaning up to get the space back.

Uninstall

Delete the binary and ~/.symposer, then run composer install in your projects to replace the links with real folders.

Cleaning up

The store keeps every version any project has ever used. Say shop and blog both use monolog 3.9.0, and you update shop to 3.10.0. Deleting 3.9.0 right away would break blog, so symposer keeps it.

To tell what's still needed, every symposer run records which store versions that project uses, in ~/.symposer/projects/. store prune reads those records and deletes the versions no project uses:

$ symposer store prune --dry-run   # list what would be deleted
$ symposer store prune             # delete it
removed 14 version(s), 38.2 MB; kept 112, used by 6 project(s)

In the example, 3.9.0 stays as long as blog uses it. Once you update blog too, or delete its folder, the next prune removes it.

Prune automatically

Set SYMPOSER_AUTO_PRUNE=1 and symposer prunes after every successful install, update, require or remove. It's off unless you turn it on.

$ echo 'export SYMPOSER_AUTO_PRUNE=1' >> ~/.zshrc   # or ~/.bashrc

Auto-prune follows the same rules and prints one line when it frees space:

symposer: auto-pruned 3 unused version(s) from the store, 9.4 MB freed

Good to know

  • Run symposer install once in older projects first. Projects last installed with symposer before 0.2.0 have no record yet, so prune would treat their versions as unused.
  • A pruned version is easy to get back. If a project lost one, run symposer install in it. Composer downloads the version again, from its cache when it can.
  • Versions stored in the last hour are skipped, so prune never races an install running in another terminal.

Troubleshooting

Permission denied writing inside vendor/some/package
That package modifies its own files. Add it to extra.symposer.exclude and run symposer install again.
php not found on PATH
Install PHP, or point SYMPOSER_PHP at the binary you want.
PHP 7.2.5+ required
Your default php is too old for Composer 2.11. Set SYMPOSER_PHP to a newer one.
A bin script can't find vendor/autoload.php
Packages with bin entries are hardlinked to avoid this. If a package finds files some other way, exclude it and open an issue with its name.

Contributing

Bug reports, package compatibility notes and pull requests are all welcome. If a package misbehaves when linked, an issue with its name and the error is already a big help.

$ git clone https://github.com/Mello21century/symposer.git && cd symposer
$ go build -o bin/symposer .
$ e2e/run.sh bin/symposer                 # needs php and network
$ E2E_LARAVEL=1 e2e/run.sh bin/symposer   # adds a full Laravel + Pest run
  • main.go is the CLI: it finds PHP, downloads Composer, and implements store.
  • shim/symposer.php is the store logic that runs inside Composer. Keep it PHP 7.2.5 compatible.
  • e2e/run.sh is the end-to-end suite. CI runs it on Linux, macOS and Windows, and on PHP 7.2 through 8.4.

Open an issue first for larger changes, so we can agree on the approach.
