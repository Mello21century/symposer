Every Composer package, stored once.

symposer runs Composer's own install, then links each package in vendor/ to one shared copy in ~/.symposer/store. A second Laravel app needs 2.6 MB of new disk instead of 77 MB.

$ curl -fsSL -o symposer "https://github.com/Mello21century/symposer/releases/latest/download/symposer-$(uname -s | tr A-Z a-z)-$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/')"
$ chmod +x symposer && sudo mv symposer /usr/local/bin/
> $dir = "$env:LOCALAPPDATA\symposer"; New-Item -ItemType Directory -Force $dir | Out-Null
> Invoke-WebRequest https://github.com/Mello21century/symposer/releases/latest/download/symposer-windows-amd64.exe -OutFile "$dir\symposer.exe"
> [Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path", "User") + ";$dir", "User")
$ go install github.com/Mello21century/symposer@latest

Measured on a second Laravel app

A fresh laravel/laravel install with the same lock file as a project you already have. Time is about the same, since Composer still generates the autoloader.

composer install77 MB
symposer install2.6 MB
New disk used by vendor/ when its packages are already in the store.

Composer still does the work

symposer doesn't resolve or download anything itself. It runs the real Composer pipeline and only changes where archives get extracted, so the rest of your setup behaves as before.

Private packages
auth.json, COMPOSER_AUTH, GitHub and GitLab tokens, Private Packagist, SSH keys.
Path repositories
Local packages you're editing stay as Composer's own symlinks and never enter the store.
Plugins and scripts
post-autoload-dump, package:discover, Flex recipes, and every plugin event fire as usual.
Custom install paths
composer/installers and installer-paths for WordPress or Drupal get their link where they expect it.
Lock file and metadata
composer.lock, installed.php, InstalledVersions and vendor/bin are untouched.
Plain Composer
Plain composer still works in the same project. Packages it installs or updates become regular folders.

What ends up in vendor/

Store files are read-only, so a package that writes into itself fails loudly instead of changing every project that shares it.

PackageBecomes
Regular dist packagelink to the store
Package with bin scriptshardlinks so __DIR__ finds your autoloader
Path repositoryComposer's link to your local folder
Git source installclone in place
Patched or excludedcopy in place

Pick the PHP per command

Composer runs on whichever PHP you name, from 7.2.5 up, so platform checks match that project. Store entries are keyed by exact version and commit, so projects on different PHP versions share it safely.

# default PHP is 8.3, this project needs 7.4
$ SYMPOSER_PHP=php7.4 symposer install
$ SYMPOSER_PHP=/opt/homebrew/opt/php@8.1/bin/php symposer update

# check which PHP and Composer will run
$ SYMPOSER_PHP=php7.4 symposer --version
